4. Verify safeguards

These requests are deliberately invalid. A 403 or 422 confirms rejection. Profile values stay unchanged.

Log out, then use Current session to confirm 401. Log in as student-b to check that student-a’s edits are private.

5. Search events

Sign in to search published events. Eligibility is based on your profile unless you supply a year/department filter. Date ranges select overlapping events.

6. Ask an event question

Limited rule baseline: try “free ML workshops this week”, “events tomorrow”, or “workshops for second years on Friday”. Questions are independent; follow-ups and room/faculty queries are not supported yet.

Each new question gets a new request ID; retries reuse it.

7. Admin event management

Sign in as admin. Create a record, switch to a student and search for it. Load the record before editing; stale versions return 409. Prices are in paise (100 paise = ₹1). All demo timestamps include an explicit UTC offset.
